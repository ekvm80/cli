가장 간단 — 최단 경로 요약

전체를 읽을 시간이 없다면 이 순서만 따라 하면 됩니다. 각 단계 끝의 절 번호에 자세한 설명과 문제 해결 방법이 있습니다.

1. 터미널 열기

  1. 키보드에서 Windows 키 를 누릅니다 (창문 모양이 그려진 키, 보통 왼쪽 Ctrl 옆에 있습니다).
  2. 나타난 검색창에 터미널 이라고 입력합니다.
  3. 터미널 이라는 앱이 나오면 Enter 를 누릅니다.

검은색(또는 파란색) 창이 열리고 이런 글자가 보이면 성공입니다.

PS C:\Users\홍길동>

→ 자세히: 2.1절

2. Node.js 설치하기

터미널에 아래를 입력하고 Enter.

winget install --id OpenJS.NodeJS.LTS -e

확인 — 기존 터미널을 닫고 새 터미널에 입력합니다.

node --version

이런 결과가 나오면 성공입니다. 숫자는 달라도 됩니다.

v24.9.0

→ 자세히: 3.2절

3. Git 설치하기

터미널에 아래를 입력하고 Enter.

winget install --id Git.Git -e

확인 — 터미널을 새로 열고 입력합니다.

git --version

git version 2.52.0.windows.1

이런 결과가 나오면 됩니다. 안 나오면 터미널을 새로 켜서 다시 설치하세요.

→ 자세히: 3.3절

4. AI 에이전트 설치하기

구독 중인 것 하나만 설치하면 됩니다.

a. Claude Code (Claude 구독자)

irm https://claude.ai/install.ps1 | iex

npm install -g @anthropic-ai/claude-code

irm https://chatgpt.com/codex/install.ps1 | iex

안 되면

npm install -g @openai/codex

그래도 안 되면

winget install --id OpenAI.Codex -e

확인 — 터미널을 완전히 닫고 새로 연 뒤 입력합니다.

codex --version

6. Orca 로 여러 에이전트를 동시에 (선택)

Orca는 여러 AI 코딩 에이전트를 동시에 돌리기 위한 프로그램입니다. 4단계까지 마쳤다면 준비는 이미 끝났습니다.

a. 설치하기

  1. 웹브라우저로 https://www.onorca.dev 에 접속합니다.
  2. Download 버튼을 누릅니다.
  3. Windows 용 설치 파일(orca-windows-setup.exe)을 내려받습니다.
  4. 내려받은 파일을 더블클릭합니다.
  5. 설치 창이 뜨면 기본값 그대로 계속 진행합니다.

b. 사용하기

  1. 왼쪽 Projects 옆의 폴더에 + 가 붙은 아이콘(Add Project)으로 작업할 폴더를 추가합니다. 그 폴더는 Git 저장소여야 합니다. 아니라면 그 폴더에서 터미널을 열고 git init 을 한 번 실행하세요.
  2. 프로젝트 이름 위의 +(New workspace)를 눌러 작업공간을 만듭니다.
  3. 실행 화면의 드롭다운에서 쓸 에이전트를 고르고, 평소처럼 한국어로 지시합니다.
  4. 작업공간을 두 개, 세 개 더 만들면 그게 병렬 실행입니다.

처음에는 승인 방식을 Manual 로 바꾸세요. Orca는 권한 확인을 건너뛰는 옵션이 기본으로 켜져 있습니다.

1부. 왜 터미널에서 AI를 쓰는가

1.1 지금 쓰는 AI 챗봇과 무엇이 다른가

웹브라우저에서 ChatGPT나 Claude를 쓸 때의 흐름은 이렇습니다.

나: "이 엑셀 파일 정리하는 방법 알려줘"
AI: (방법을 글로 설명해 줌)
나: (설명을 읽고 → 엑셀을 열고 → 직접 손으로 작업)

AI는 말로만 알려주고, 실제 작업은 사람이 합니다. 파일을 AI에게 하나씩 올려야 하고, AI가 준 답을 다시 복사해서 붙여넣어야 합니다.

터미널에서 쓰는 AI 에이전트는 흐름이 다릅니다.

나: "이 폴더의 엑셀 파일들 정리해줘"
AI: (폴더를 직접 열어봄 → 파일을 직접 읽음 → 직접 수정함 → 결과 보고)
나: (확인만 함)

핵심 차이는 하나입니다. AI가 내 컴퓨터의 파일을 직접 읽고 쓸 수 있다는 것.

웹 챗봇 터미널 AI 에이전트
파일 전달 하나씩 직접 업로드 폴더 통째로 알아서 읽음
결과 받기 복사해서 붙여넣기 파일로 바로 저장됨
여러 파일 작업 사실상 불가능 수백 개도 가능
반복 작업 매번 처음부터 한 번 시켜두면 알아서
작업 기억 대화창 닫으면 사라짐 폴더에 기록으로 남음

1.3 자주 하는 걱정에 대한 답

"프로그래밍을 몰라도 되나요?"

됩니다. 한국어로 "이거 해줘"라고 말하면 됩니다. 다만 터미널 창을 여는 법과 명령어 몇 개는 알아야 하는데, 그건 2부에서 다룹니다. 30분이면 익힙니다.

"내 파일을 망가뜨리면 어쩌죠?"

AI 에이전트는 파일을 수정하기 전에 "이렇게 바꿔도 될까요?"라고 매번 물어봅니다. 사용자가 승인해야만 실행합니다. 게다가 7부에서 안내하는 안전 수칙(백업, 폴더 분리)을 지키면 위험은 거의 없습니다.

"내 파일이 외부로 새어 나가나요?"

AI가 읽은 파일 내용은 답변을 만들기 위해 서버로 전송됩니다. 이건 웹 챗봇에 파일을 업로드하는 것과 같습니다. 개인정보, 미공개 연구 데이터, 회사 기밀은 작업 폴더에 두지 마세요. 자세한 내용은 7부에 있습니다.

"돈이 드나요?"

기본적으로 유료 구독이 필요합니다. 이미 ChatGPT Plus나 Claude Pro를 쓰고 있다면 추가 비용 없이 그 구독으로 이용할 수 있습니다. Google의 Antigravity CLI는 Google 계정으로 로그인하면 일정량을 무료로 쓸 수 있습니다(정확한 한도는 공식 문서를 확인하세요). 4.1절에 정리해 두었습니다.

"리눅스를 깔아야 하나요? WSL이 필요한가요?"

아닙니다. Windows에서 그대로 쓰면 됩니다. 예전에는 일부 도구가 Windows를 지원하지 않아 WSL(리눅스 환경)이 필요했고 그 시절 자료가 아직 많이 남아 있지만, 지금은 세 도구 모두 Windows 전용 설치본을 제공합니다. 자세한 판단 기준은 부록 D에 있습니다.

"검은 화면이 무서워요."

가장 흔한 반응입니다. 하지만 실제로 쓰는 명령어는 5개 정도이고, 나머지는 전부 한국어로 대화하는 것입니다. 검은 화면은 그냥 AI와 대화하는 창이라고 생각하면 됩니다.

2부. 터미널 기초 — 30분이면 충분합니다

프로그래머가 되려는 게 아닙니다. AI에게 일을 시킬 수 있을 정도만 배웁니다.

2.1 터미널이란 무엇인가

터미널은 컴퓨터에게 글자로 명령을 내리는 창입니다.

평소에는 마우스로 폴더를 더블클릭해서 엽니다. 터미널에서는 cd 폴더이름이라고 타이핑해서 엽니다. 결과는 똑같습니다. 방법만 다릅니다.

왜 굳이 이걸 쓰냐면, AI 에이전트가 이 방식으로만 동작하기 때문입니다. 마우스로 클릭하는 화면이 없습니다.

터미널 열어보기

  1. 키보드에서 Windows 키 를 누릅니다 (창문 모양이 그려진 키, 보통 왼쪽 Ctrl 옆에 있습니다).
  2. 나타난 검색창에 터미널 이라고 입력합니다.
  3. 터미널 이라는 앱이 나오면 Enter 를 누릅니다.

검은색(또는 파란색) 창이 열리고 이런 글자가 보일 겁니다.

PS C:\Users\홍길동>

이게 정상입니다. 뜻은 이렇습니다.

  • PS = PowerShell(파워셸)의 약자. 명령을 받아주는 프로그램 이름입니다.
  • C:\Users\홍길동 = 지금 내가 있는 위치(폴더). 이게 가장 중요합니다.
  • > = "명령을 입력하세요"라는 신호. 이 뒤에 타이핑하면 됩니다.

기억할 것: 터미널에는 항상 "현재 위치"가 있습니다. 탐색기 창에서 특정 폴더를 열어둔 상태와 똑같습니다. 명령은 모두 그 위치를 기준으로 실행됩니다.

2.2 명령어의 구조

명령어는 대부분 이 형태입니다.

명령어 대상 -옵션

예를 들어 보겠습니다.

cd Documents
  • cd = 명령어 ("이 폴더로 이동해라"라는 뜻, change directory의 약자)
  • Documents = 대상 (이동할 폴더 이름)

명령어를 입력한 뒤에는 반드시 Enter 를 눌러야 실행됩니다. Enter를 누르기 전까지는 아무 일도 일어나지 않으니, 오타가 나도 당황하지 말고 지우면 됩니다.

2.3 폴더와 경로 이해하기

컴퓨터의 폴더는 서랍장처럼 층층이 들어 있습니다.

C:\                          ← C드라이브 (가장 바깥)
└── Users\                   ← 사용자 폴더
    └── 홍길동\               ← 내 폴더
        ├── Documents\        ← 문서
        ├── Downloads\        ← 다운로드
        └── Desktop\          ← 바탕화면

이걸 한 줄로 쓴 것이 경로(path) 입니다.

C:\Users\홍길동\Documents

역슬래시(\)가 서랍의 구분선입니다. 한글 키보드에서는 원화 기호(₩)로 보이는데, 같은 글자입니다. 걱정하지 마세요.

경로를 손으로 타이핑하지 않는 방법 (중요)

경로를 직접 입력하면 오타가 나기 쉽습니다. 훨씬 쉬운 방법이 있습니다.

방법 1 — 탐색기에서 복사하기
1. 파일 탐색기에서 원하는 폴더를 엽니다.
2. 위쪽 주소창을 한 번 클릭합니다. 경로가 글자로 바뀝니다.
3. Ctrl + C 로 복사합니다.
4. 터미널에서 cd 를 입력하고 (cd 다음에 한 칸 띄고), 마우스 오른쪽 버튼을 한 번 클릭하면 붙여넣기가 됩니다.

방법 2 — 탐색기에서 바로 터미널 열기 (가장 편함)
1. 파일 탐색기에서 원하는 폴더를 엽니다.
2. 폴더 안 빈 공간에 마우스 오른쪽 클릭을 합니다.
3. "터미널에서 열기" 를 선택합니다.

이러면 그 폴더 위치에서 터미널이 바로 열립니다. 앞으로 이 방법을 주로 쓰게 됩니다.

주의: 경로에 띄어쓰기가 있으면 큰따옴표로 감싸야 합니다.
틀림: cd C:\내 문서\연구 자료
맞음: cd "C:\내 문서\연구 자료"

2.4 꼭 알아야 할 명령어 5개

이것만 알면 됩니다.

아래 명령은 PowerShell(2.1절에서 연 터미널 앱의 기본값)에서 동작합니다. 옛 명령 프롬프트(cmd)에서는 ls, pwd 가 없어 오류가 납니다. 프롬프트가 PS C:\...> 로 시작하면 PowerShell, C:\...> 로만 시작하면 명령 프롬프트입니다. 후자라면 창을 닫고 터미널 앱을 새로 여세요.

① cd — 폴더 이동하기

cd ..

점 두 개는 한 단계 위로(바깥으로) 나가기입니다.

cd \

② ls — 지금 폴더에 뭐가 있는지 보기

ls

현재 폴더의 파일과 폴더 목록이 나옵니다. 탐색기로 폴더를 들여다보는 것과 같습니다.

③ pwd — 내가 지금 어디 있는지 확인

pwd

현재 위치의 전체 경로를 보여줍니다. 길을 잃었을 때 씁니다.

④ mkdir — 새 폴더 만들기

mkdir 내연구

현재 위치에 내연구라는 폴더가 생깁니다.

⑤ cls — 화면 지우기

cls

화면이 지저분해졌을 때 깨끗하게 만듭니다. 파일이 지워지는 게 아니라 화면만 정리됩니다.

AI 에이전트를 설치하기 전에, 그것이 돌아가는 데 필요한 프로그램들을 먼저 깝니다.

3.0 무엇을 왜 설치하는가

순서 프로그램 왜 필요한가 필수 여부 시간
1 Windows Terminal AI와 대화할 창. 기본 창은 한글이 깨집니다 필수 2분
2 Node.js npm 방식으로 설치할 때 필요한 엔진 권장 5분
3 Git AI가 내부적으로 사용. Claude Code는 이게 있으면 Git Bash를 셸로 씁니다 권장 5분

모두 무료이고 안전한 공식 프로그램입니다.

실행 정책·한글 깨짐 설정은 지금 하지 않습니다.
예전에는 설치 전에 미리 해 두라고 안내했지만, 요즘 설치본은 대부분 이 설정 없이도 그대로 설치됩니다. 필요 없는 설정을 미리 건드릴 이유가 없으므로 부록 E 로 옮겼습니다. 설치나 실행 중에 스크립트를 실행할 수 없으므로 또는 한글이 ??? 로 깨지는 문제가 생기면 그때 부록 E를 보고 처리하세요.

Node.js가 "권장"인 이유
예전에는 AI 에이전트가 전부 npm(Node.js에 포함된 설치 도구)으로만 설치됐습니다. 지금은 Claude Code·Antigravity CLI·Codex CLI 모두 Node.js 없이 바로 설치되는 전용 설치본을 제공합니다. 그래도 Node.js를 깔아두길 권합니다. 설치 문제가 생겼을 때 대안 경로가 되고, AI가 만드는 도구 중 상당수가 Node.js를 씁니다. 시간을 아끼고 싶다면 3.2절을 건너뛰고 4부로 가도 됩니다.

3.1 Windows Terminal 설치

Windows 11에는 대부분 이미 설치되어 있습니다. 2.1절에서 터미널이 잘 열렸다면 이 단계는 건너뛰세요.

없다면 터미널(또는 명령 프롬프트)에 아래를 입력합니다.

winget install --id Microsoft.WindowsTerminal -e

3.2 Node.js 설치 (권장)

Node.js는 프로그램을 실행하고 설치해 주는 기반 엔진입니다. AI 에이전트를 npm 방식으로 설치할 때 쓰이고, AI가 만들어 주는 도구를 돌릴 때도 자주 필요합니다.

설치 방법 A — 명령어로 (권장, 빠름)

터미널에 아래를 입력하고 Enter.

winget install --id OpenJS.NodeJS.LTS -e

설치가 진행되고 몇 분 걸립니다. 설치 완료 또는 Successfully installed 라는 글자가 나오면 끝입니다.

설치 방법 B — 홈페이지에서 내려받기

명령어가 안 먹히면 이 방법을 씁니다.

  1. 웹브라우저로 https://nodejs.org 에 접속합니다.
  2. 초록색 버튼 중 "LTS" 라고 쓰인 것을 클릭합니다. (LTS = 장기 지원 안정 버전. Current 버전은 고르지 마세요.)
  3. 내려받은 파일(node-v24...msi)을 더블클릭합니다.
  4. 설치 창이 뜨면 아무것도 바꾸지 말고 계속 "Next" 를 누릅니다.
  5. Automatically install the necessary tools... 체크박스가 나오면 체크하지 마세요. (필요 없고 오래 걸립니다.)
  6. "Install" → 완료되면 "Finish".

제대로 됐는지 확인하기 (반드시 하세요)

터미널 창을 완전히 닫고, 새로 엽니다. (이 과정을 빼먹으면 설치했는데도 안 된다고 나옵니다.)

새 터미널에 입력합니다.

node --version

이런 결과가 나오면 성공입니다.

v24.9.0

숫자는 달라도 됩니다. v 로 시작하는 버전 번호가 나오면 됩니다. (2026년 9월 기준 LTS는 24.x 계열이고, 22.x도 아직 지원됩니다.)

npm --version

이것도 확인합니다. 10.9.2 같은 숫자가 나오면 됩니다.

node는 무엇이고 npm은 무엇인가요?
node는 엔진이고, npm은 프로그램을 설치해 주는 도구입니다. Node.js를 깔면 둘 다 같이 설치됩니다.

안 될 때

'node'은(는) ... 인식되지 않습니다 라고 나온다면:

  1. 터미널을 닫고 새로 열었는지 확인하세요. (가장 흔한 원인입니다.)
  2. 그래도 안 되면 컴퓨터를 재부팅하고 다시 확인하세요.
  3. 그래도 안 되면 8.1절을 보세요.

3.3 Git 설치

Git은 원래 프로그래머가 파일 변경 이력을 관리하는 도구인데, AI 에이전트가 내부적으로 사용합니다. 사용법을 배울 필요는 없고, 깔아두기만 하면 됩니다.

Windows에서는 이유가 하나 더 있습니다. Git을 설치하면 함께 깔리는 Git Bash를 Claude Code가 자동으로 감지해 명령 실행용 셸로 씁니다. 인터넷에 널려 있는 리눅스식 명령어가 그대로 통해서 오류가 눈에 띄게 줄어듭니다. 필수는 아니지만 깔아두는 편이 낫습니다.

winget install --id Git.Git -e

홈페이지에서 받으려면 https://git-scm.com/download/win 에서 내려받아 설치합니다. 설치 창에서 선택 항목이 많이 나오는데, 전부 기본값 그대로 두고 Next 를 눌러도 문제없습니다.

확인하기

터미널을 새로 열고 입력합니다.

git --version

git version 2.52.0.windows.1

이런 결과가 나오면 됩니다.

4.4 Antigravity CLI 설치 (Gemini CLI의 후속)

먼저 알아둘 것 — Gemini CLI는 끝났습니다

Google은 2026년 5월 19일 Gemini CLI와 Gemini Code Assist IDE 확장의 개인 사용자 지원 종료를 발표했고, 2026년 6월 18일부로 실제 서비스가 중단되었습니다. 후속 도구가 Antigravity CLI이며 터미널 명령어는 agy 입니다.

Gemini CLI (종료) Antigravity CLI (현행)
명령어 gemini agy
설치 npm install -g @google/gemini-cli 전용 설치 스크립트
형태 오픈소스(TypeScript), npm 패키지 Google 배포 실행 파일
규칙 파일 GEMINI.md AGENTS.md

아직 Gemini CLI를 쓸 수 있는 경우: Gemini Code Assist Standard/Enterprise 라이선스 보유자, Google Cloud를 통한 Code Assist for GitHub 사용자, 유료 Gemini API 키 보유자. 여기 해당하지 않는 개인 사용자는 로그인 자체가 되지 않습니다.

이미 Gemini CLI를 깔아두었다면 먼저 지웁니다.

npm uninstall -g @google/gemini-cli

설치

관리자 권한이 아닌 일반 PowerShell에 입력합니다.

irm https://antigravity.google/cli/install.ps1 | iex

설치본은 C:\Users\사용자이름\AppData\Local\agy\bin 에 들어가고, 설치 스크립트가 PATH 등록까지 해 줍니다.

명령 프롬프트(cmd)를 쓴다면 대신 이렇게 합니다.
curl -fsSL https://antigravity.google/cli/install.cmd -o install.cmd && install.cmd && del install.cmd

5.0 먼저 외울 것 — 필수 명령어 5개

대화창 안에서 쓰는 것은 사실상 이 다섯 개입니다. 이것만 알면 막히지 않습니다.

하려는 것 입력 설명
터미널로 돌아가기 Ctrl + C 를 두 번 한 번은 진행 중인 작업 중단, 두 번은 대화창 종료. 뭔가 잘못 돌아갈 때 가장 먼저 누릅니다
모델 선택 /model 쓸 모델을 고릅니다. 가벼운 모델은 빠르고 사용량을 덜 먹고, 무거운 모델은 어려운 일에 강합니다

사용량 확인 /usage 남은 사용량과 한도가 언제 회복되는지 봅니다

도구마다 명령이 조금씩 다릅니다.
위 다섯 개는 Claude Code 기준입니다. Codex CLI·Antigravity CLI 는 이름이 다르거나 없는 것도 있습니다. 대화창에서 /help 를 입력하면 그 도구가 실제로 가진 명령과 단축키가 전부 나옵니다. 막히면 /help 부터 보세요.

사용량은 "일정 기간" 단위로 회복됩니다

구독료를 냈다고 무한히 쓸 수 있는 게 아닙니다. AI 회사들은 정해진 기간 안에 쓸 수 있는 양(토큰) 을 배정하고, 그 기간이 지나면 다시 채워 줍니다. 그래서 한도에 걸려도 기다리면 풀립니다.

도구 짧은 주기 긴 주기 남은 양 확인
Claude Code 5시간 단위 주(7일) 단위 한도가 추가로 있음 /usage
Codex CLI 5시간 단위 주(7일) 단위 한도가 추가로 있음 /status
Antigravity CLI 5시간 단위 요금제에 따라 다름 /usage

읽는 방법 — "5시간 단위"는 처음 지시를 보낸 시점부터 5시간이 한 묶음이라는 뜻입니다. 그 안에서 배정량을 다 쓰면 다음 묶음이 시작될 때까지 기다려야 합니다. 여기에 주 단위 한도가 겹쳐 있어서, 며칠 몰아서 많이 쓰면 5시간 한도가 남아 있어도 주 한도에 먼저 걸릴 수 있습니다.

정확한 수치는 여기 적지 않습니다.
배정량은 요금제(Pro·Max·Plus 등)와 시점에 따라 자주 바뀝니다. 숫자를 외우는 대신 /usage 로 그때그때 확인하는 습관을 들이세요.

사용량을 아끼는 방법 3가지

  • 주제가 바뀌면 /clear — 대화가 길어지면 이전 내용을 매번 다시 읽어 들여 사용량을 많이 먹습니다. 새 주제를 시작할 때는 대화를 비우세요.
  • 쉬운 일은 가벼운 모델로 — /model 로 바꿉니다. 파일 정리나 단순 변환에 무거운 모델을 쓸 이유가 없습니다.
  • 작업 폴더를 작게 유지 — AI가 훑어야 할 파일이 적을수록 덜 먹습니다. 7부의 "전용 작업 폴더" 원칙이 사용량 측면에서도 유리합니다.

여기서부터는 길이 둘로 갈립니다. 어느 쪽을 먼저 해도 괜찮습니다. 순서가 정해져 있지 않고, 한쪽을 했다고 다른 쪽을 못 하는 것도 아닙니다.

이어서 볼 곳 아래 5.1절부터 계속 Orca 입문 가이드

① 터미널에서 연습하기 — 아래 5.1절부터 그대로 읽으면 됩니다. 도구가 실제로 무엇을 하는지, 승인 화면이 어떻게 생겼는지 눈으로 익히기에는 이쪽이 낫습니다. 문제가 생겼을 때 원인을 찾는 감각도 여기서 생깁니다.

② Orca로 바로 써보기 — 검은 화면이 부담스럽거나, 처음부터 여러 작업을 동시에 돌려보고 싶다면 이쪽입니다. Orca 입문 가이드 로 넘어가세요. Orca는 4부에서 설치한 AI CLI를 그대로 가져다 쓰므로, 4부까지 마쳤다면 준비는 이미 끝났습니다.

권하는 순서: ①을 30분 해보고 ②로 넘어가는 것입니다. Orca는 결국 4부의 도구들을 여러 개 띄우는 껍데기라서, 그 도구가 무엇인지 알고 나면 훨씬 쉽게 이해됩니다. 다만 이건 권유일 뿐이고, ②부터 시작해도 아무 문제 없습니다.

AI가 파일을 수정하거나 만들려고 할 때, 이런 화면이 나옵니다.

파일을 만들려고 합니다: 매출정리.md

  1. Yes                        (한 번만 허용)
  2. Yes, and don't ask again   (앞으로 계속 허용)
  3. No, tell Claude what to do  (거부하고 다른 지시)

화살표 키로 고르고 Enter를 누릅니다.

초보자를 위한 원칙

  • 읽기만 하는 작업 → 1. Yes 로 편하게 허용
  • 파일을 새로 만드는 작업 → 1. Yes
  • 기존 파일을 고치거나 지우는 작업 → 내용을 꼼꼼히 읽고 판단
  • 2번(계속 허용)은 처음엔 고르지 마세요. 익숙해진 뒤에 쓰세요.
  • 이상하다 싶으면 3. No 를 고르고 "그건 하지 말고 대신 ○○해줘" 라고 말하면 됩니다.

작업을 중간에 멈추고 싶으면 Ctrl + C 를 누릅니다.

5.5 종료하기

대화창에서 이렇게 입력하면 끝납니다.

exit

또는 Ctrl + C 를 두 번 누릅니다.

  2. 빈 공간에 마우스 오른쪽 클릭 → "터미널에서 열기".
  3. claude 입력. (또는 codex / agy)

로그인은 이미 되어 있으므로 바로 시작됩니다.

6.5 좋은 지시문 쓰는 요령

나쁜 예 좋은 예

"분석해줘" "월별 평균과 전월 대비 증감률을 계산해서 표로 만들어줘"
"고쳐줘" "맞춤법과 띄어쓰기만 고치고, 문장 구조는 바꾸지 마"

요령 4가지

  1. 무엇을 할지 + 어떻게 할지 + 결과를 어디에 저장할지를 함께 말합니다.
  2. 위험한 작업은 "먼저 계획을 보여주고, 내가 승인하면 실행해" 라고 덧붙입니다.
  3. 원본을 지키고 싶으면 "원본은 건드리지 말고 사본을 만들어" 라고 명시합니다.

7부. 안전하게 쓰기 — 꼭 지킬 5가지

① 전용 작업 폴더에서만 실행하기

AI 에이전트는 실행한 폴더와 그 아래를 작업 범위로 삼습니다.

  • 하지 마세요: 바탕화면, C:\Users\내이름, C드라이브 최상위에서 실행
  • 하세요: C:\AI작업\프로젝트1 처럼 목적별 폴더를 만들어 그 안에서 실행

② 원본은 미리 복사해 두기

AI가 파일을 잘못 고칠 수도 있고, 내가 승인을 잘못 누를 수도 있습니다.

작업 전에 폴더를 통째로 복사해 두세요. 가장 확실하고 간단한 안전장치입니다.

③ 민감한 정보는 작업 폴더에 두지 않기

AI가 읽은 파일 내용은 답을 만들기 위해 서버로 전송됩니다.

작업 폴더에 두지 말아야 할 것:
- 주민등록번호, 계좌번호, 비밀번호가 들어간 파일
- 미공개 연구 데이터, 심사 중인 논문 원고
- 회사 기밀, 계약서
- 다른 사람의 개인정보가 담긴 명단

기관 규정상 외부 전송이 금지된 자료는 애초에 가져오지 마세요.

④ 승인 화면을 읽고 누르기

빨리 넘기려고 무조건 Yes 를 누르는 습관은 위험합니다. 무엇을 하려는지 한 번은 읽으세요.

특히 이런 단어가 보이면 멈추고 확인합니다: 삭제(delete, rm), 덮어쓰기(overwrite), 전체(all), 강제(force)

⑤ 자동 승인 기능은 쓰지 않기

Claude Code의 --dangerously-skip-permissions, Codex CLI의 --full-auto/--yolo, Antigravity CLI의 자동 승인(auto-approve) 설정은 모두 "묻지 말고 다 해라"라는 뜻입니다. 이름 그대로 위험합니다. 초보자는 절대 쓰지 마세요.

인터넷의 팁 글에서 "이거 켜면 편하다"라고 권하는 경우가 있는데, 그건 잘못 지워도 복구 가능한 코드 저장소에서 작업하는 사람들 기준입니다. 원본 데이터가 든 폴더에서는 쓰지 마세요.

curl -fsSL https://antigravity.google/cli/install.sh | bash

Codex CLI는 Homebrew로 설치합니다.

brew install --cask codex

npm install -g ... 방식은 Windows와 완전히 같습니다.

부록 D. WSL(리눅스)을 써야 하나요?

결론: 이 가이드의 독자라면 그냥 Windows에서 쓰세요.

인터넷에서 "Claude Code는 WSL이 필요하다"는 글을 보게 될 텐데, 대부분 2024~2025년에 쓰인 글입니다. 당시에는 실제로 Windows를 지원하지 않아 WSL(Windows Subsystem for Linux, Windows 안에서 리눅스를 돌리는 기능)이 유일한 방법이었습니다. 지금은 세 도구 모두 Windows 전용 설치본을 제공하며, WSL은 필요 없습니다.

그냥 Windows를 쓰는 게 나은 이유

Windows 그대로 WSL
설치 명령 한 줄 리눅스 설치 + 그 안에 다시 전부 설치
Windows 파일 접근 D:\연구자료 그대로 /mnt/d/연구자료 로 우회, 느림
한글 파일명·경로 문제없음 깨지는 경우가 있음
한글 문서·엑셀 작업 자연스러움 불편함
배워야 할 것 없음 리눅스 개념이 하나 더

특히 작업 대상이 Windows 폴더의 문서·데이터라면 WSL은 손해입니다. WSL에서 Windows 드라이브(/mnt/c, /mnt/d)를 읽고 쓰는 속도는 눈에 띄게 느리고, 파일이 수백 개가 되면 체감이 큽니다.

대신 이것만 하세요

Windows에서 쓸 때 마찰을 줄이는 방법은 WSL이 아니라 Git for Windows 설치입니다(3.3절). Claude Code가 Git Bash를 감지하면 PowerShell 대신 그걸 셸로 쓰는데, 인터넷 자료와 AI가 알고 있는 명령어가 대부분 리눅스식이라 오류가 줄어듭니다.

WSL이 나은 경우

다음에 해당한다면 WSL을 고려할 만합니다. 대부분의 독자는 해당하지 않습니다.

  • 리눅스 전용 개발 도구(도커, 특정 파이썬 패키지 등)를 써야 한다
  • 서버에 올릴 프로그램을 만들고 있고, 개발 환경을 서버와 맞춰야 한다
  • AI에게 위험한 작업을 시키면서 Windows 본체와 격리하고 싶다

WSL을 쓰기로 했다면, 작업 파일도 WSL 안쪽(~/projects/...)에 두세요. Windows 드라이브를 오가는 방식이 가장 느리고 문제도 많습니다.

E.1 실행 권한 설정

Windows는 보안상 외부 스크립트 실행을 기본으로 막아둡니다. 설치나 실행이 이 때문에 막힐 때 풀어 줍니다.

터미널에 입력합니다.

Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned

실행 정책을 변경하시겠습니까? 라고 물으면 Y 를 입력하고 Enter.

위험하지 않나요?
RemoteSigned는 "내가 만든 스크립트는 실행하고, 인터넷에서 받은 것은 서명된 것만 실행한다"는 중간 단계 설정입니다. 개발자들이 표준으로 쓰는 설정이며, 보안을 완전히 푸는 게 아닙니다. -Scope CurrentUser 때문에 내 계정에만 적용되고 컴퓨터 전체에는 영향이 없습니다.

지금 설정을 확인만 하고 싶으면 이렇게 입력합니다.

Get-ExecutionPolicy -Scope CurrentUser

E.2 한글 깨짐 방지 설정

한글 파일명이나 한글 답변이 ??? 나 占쏙옙 처럼 깨져 보일 때만 하면 됩니다.

임시로 넘기려면 터미널에 한 줄 입력합니다. 창을 닫으면 원래대로 돌아갑니다.

chcp 65001

매번 자동으로 적용하려면 프로필 파일에 적어 둡니다. 터미널에 아래를 입력합니다.

notepad $PROFILE

메모장이 열립니다. "파일을 찾을 수 없습니다. 새로 만드시겠습니까?" 라고 물으면 "예" 를 누릅니다.

메모장에 아래 3줄을 복사해서 붙여넣습니다.

[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
[Console]::InputEncoding  = [System.Text.Encoding]::UTF8
$PSDefaultParameterValues['*:Encoding'] = 'utf8'

Ctrl + S 로 저장하고 메모장을 닫습니다. 터미널도 닫았다가 새로 엽니다.

이 파일($PROFILE)은 터미널을 켤 때마다 자동으로 실행되는 설정 파일입니다. 여기 적어두면 매번 손댈 필요가 없습니다.

그래도 안 되면 8.3절의 Windows 시스템 로캘 변경까지 검토하세요.

마무리 — 다음 단계

여기까지 왔다면 기본기는 끝났습니다. 익숙해진 뒤 이런 것들을 시도해 보세요.

  1. 작업 폴더에 안내 파일 두기 — 폴더에 규칙 파일을 만들어 "이 폴더에서는 이런 규칙으로 작업해줘"라고 적어두면, 매번 설명하지 않아도 AI가 알아서 지킵니다. Claude Code는 CLAUDE.md, Codex CLI와 Antigravity CLI는 AGENTS.md 를 읽습니다. Claude Code에서는 /init 명령으로 초안을 자동 생성할 수 있습니다.

  2. 자주 쓰는 지시를 저장해 두기 — 반복하는 작업의 지시문을 메모장에 모아두고 복사해서 씁니다.

  3. 외부 서비스 연결(MCP) — 구글 드라이브, 노션 같은 서비스를 AI에 직접 연결할 수 있습니다. 기본 사용에 익숙해진 뒤에 도전하세요.

  4. 여러 도구 비교해 보기 — 같은 일을 Claude / Codex / Antigravity에 각각 시켜보면 성격 차이를 알게 됩니다.
